# SpiderCaster - a website building engine on free and nearly-free tokens

Standalone CLI, and a Cosmos motif plugin. `plugin/cosmos.json` is the
contract: hosts `standalone`, `cosmos`, and `cosmos-code`. Installed, it is
the Spidercaster tab on the cDeck left sidebar (`website`). That page edits
role labels, models, and workflow order. Hands stay in this package. Publish
stays a human click. Set `SPIDERCASTER_HOME` to this directory on a machine
that does not use the default path.

Copy-driven static site engine for the WebDev fleet. Real copy in, self-contained
static site out. The structure, layout and assembly are deterministic code, so
the bulk of every build costs **zero tokens**. AI is optional and rides the free
chain; paid models join only on an explicit flag.

Built to the WebDev package rails: no invented content, noindex by default, no
hotlinking, secrets by env var NAME only, Python 3.11+ stdlib only (no pip deps),
and a token ledger on every run.

## Install

None. Python 3.11+ with stdlib only.

```
cd SpiderCaster
python spidercaster.py --help
```

### Setup

Python 3.11+ and nothing else (stdlib only, no pip). Windows is the reference platform (PowerShell).

```
git clone https://github.com/SpiderCaster/COSMOS-SC.git
cd COSMOS-SC
python spidercaster.py doctor          # prints JSON; "ok": true means molds, frames, seats and hands line up
powershell -File scripts\install_hooks.ps1   # install the pre-commit secret scan (once per clone)
```

### Run

See Quickstart below. The short version, no keys needed:

```
python spidercaster.py build projects/demo-local --offline --out sites/demo-local
python spidercaster.py check sites/demo-local --expect-noindex
python spidercaster.py serve sites/demo-local
```

`python mcp_server.py` starts the MCP server on stdio (see `mcp/HARNESS_CONFIGS.md`).

### Tests and selftests

Run from the repo root. No keys, no network.

```
python spidercaster.py shipcheck                # the ship gate: runs the engine selftests as subprocesses, prints "shipcheck ok"
python -m unittest tests.test_secret_scan -v    # secret scanner tests
python -m lib.hands.selftest                    # each selftest can also run alone
python -m lib.mobile_selftest
python lib/check_claims_selftest.py
python lib/check_typography_selftest.py
python spidercaster.py crew selftest
python tools/sidebars-widgets/selftest.py       # sidebar suite defect-catch selftest
python bench/coldstart_bench.py --source head   # build + reproducibility + check + serve + doctor from a fresh copy of HEAD
```

Run lib selftests as modules (`-m lib.x`) or by path as listed; importing `lib.*` needs the repo root as the working directory.

### Secrets: names only, never values

- No secret value belongs in this repo. Code reads secrets from environment variables by NAME: `GEMINI_API_KEY`, `GOOGLE_API_KEY`, `FORGE_GEMINI_KEY_FILE` (a path), `OPENROUTER_API_KEY`, `OPENWORK_API_KEY`, `OPENWORK_INFERENCE_BASE_URL`.
- On the WebDev box the canonical secrets file is `V:\streams\webdev\keys\.env` (NAME=value lines, outside the repo). Never open, paste or commit it. Local tools that need it load it by NAME; `SC_KEYS_ENV` overrides its path for the local DNS helper in `V:\streams\webdev\spidercaster_local\`. `credentials.env` there holds only `${NAME}` references that resolve from the environment first, then from the keys file.
- `.gitignore` blocks `.env*` (except `.env.example` and `.env.sample`), `credentials*.env`, `keys/`, `secrets*`, key and certificate files (`*.key`, `*.pem`, `*.pfx`, `*.p12`, `*.jks`, `*.kdbx`, `id_rsa*`, `id_ed25519*`) and `*.bak`. If you need to share a config shape, commit a `.env.example` with names and empty values.
- `scripts/secret_scan.py` runs on every commit through `scripts/hooks/pre-commit` (install with `scripts\install_hooks.ps1`). It checks file names (env, credentials, key files), token shapes (OpenAI-style, GitHub, AWS, Slack, Google, Stripe, JWT, private key blocks, URLs with credentials), secret-looking assignments, and, if the keys file is readable, any literal value from it (reported as `known-value:NAME`). It prints `file:line  rule` and never the matched text.
  - `python scripts/secret_scan.py` scans staged files; `--all` scans tracked and untracked non-ignored files; `PATH ...` scans given files. Exit 1 means findings.
  - A reviewed false positive can carry `secret-scan: ignore` in a comment on that line.
- If a secret was ever committed or pasted anywhere, treat it as leaked: report the NAME to the owner so it is rotated. Do not rewrite pushed history without asking.

### Contributing

- Branch from `main` (`wip/<topic>-<date>` for catch-up work, `feat/<topic>`, `fix/<topic>`); never push straight to `main`; open a pull request.
- Keep commits logical (one purpose each) with a message that says why. No force-push or history rewrite on pushed branches.
- Before a commit run `python spidercaster.py shipcheck` and the unit tests above; the hook runs the secret scan for you.
- Do not commit generated or local output: caches, `bench/results/`, `stage/`, `preview/`, `_delme/`, key files, photos you do not own. Built demo output under `sites/` is the exception and stays tracked.
- The engine rails apply to every change: no invented content, noindex by default, no hotlinking, stdlib only, token ledger on every run.
## Token economics

| path | tokens | what happens |
|---|---|---|
| `build --offline` | 0 | copy files mapped to sections by rules; renderer assembles |
| `build --from site.json` | 0 | re-assemble after hand edits |
| `refine ... --offline` | 0 | theme flips (template/dark/light/#hex) |
| `build` (AI) | 1-2 calls | one compact planning call (+1 JSON-repair retry max) |
| `refine "..."` (AI) | 1 small call | one section patched, not the whole site |

Provider chain (cost order): Gemini free tier (AI Studio, then Vertex express
with the same key) -> OpenRouter `:free` models -> OpenWork org inference.
`--allow-paid` unlocks paid OpenRouter models; the ledger prices them from a
small list-price table. Every attempt (ok or failed) lands in `report.json`
with token counts - never key values.

## Quickstart

```
python spidercaster.py init projects/myproj          # scaffold brief.md + copy/
# fill projects/myproj/brief.md and projects/myproj/copy/*.md with REAL copy
python spidercaster.py build projects/myproj --offline --out sites/myproj
python spidercaster.py check sites/myproj --expect-noindex
python spidercaster.py serve sites/myproj            # http://localhost:4173
```

AI polish when a provider is configured:

```
python spidercaster.py models --probe                # what is reachable right now
python spidercaster.py build projects/myproj --out sites/myproj
python spidercaster.py refine sites/myproj "tighten the hero" --section hero
```

Hand-edit path (zero tokens): edit `sites/myproj/site.json`, then

```
python spidercaster.py build --from sites/myproj/site.json --out sites/myproj
```

## Copy mapping rules (offline planner)

Everything on the site comes from `copy/` files. Nothing is invented.

- First content block of `overview.md` (else `index/home/main/intro/about.md`,
  else the first file) becomes the hero: headline, lead paragraph, bullets.
- A block with 3+ bullets becomes a `features` section (icons guessed from
  keywords).
- Question paragraphs followed by answers become a `faq` section.
- Bullet lines shaped like `Name - $12` become `pricing` or `menu` rows.
- A heading matching contact becomes the `contact` section; email/phone are
  picked up from the text.
- Everything else becomes `about`-style text sections.
- Images only from local files listed in `assets.json`
  (`{"images": {"name": "path/relative/to/project.jpg"}}`). External stock
  URLs are dropped with a warning (download-only / no-hotlink rails).

## Checks (fleet-aligned)

`python spidercaster.py check SITE [--expect-noindex|--expect-indexable]`

- `no_sample` - the same fleet patterns as
  `WebDev/tools/owp-tools/scripts/website_checker.py` (SAMPLE, lorem ipsum,
  hello world, under construction, ...), grepped on raw HTML.
- `no_soft_placeholders` - TODO/TBD/FIXME/lorem/placeholder in visible text.
- `no_hotlink` - the fleet stock-CDN blocklist.
- `meta_basics` - doctype, title, description, viewport per page.
- `noindex_status` - matches the build flag (default noindex).
- `internal_links` - every `#anchor` and `page.html` link resolves.
- `token_ledger` - mode + token totals from report.json.

Exit code is nonzero on any FAIL, so it can gate a deploy conversation.

## Commands

```
init      scaffold a project (brief.md + copy/README.md)
build     project dir -> static site        [--offline | AI chain | --from site.json]
refine    patch one section of a built site [--offline for theme flips]
check     run the built-in checks
serve     preview on localhost (default port 4173, auto-increments)
models    show the provider chain           [--probe queries live]
sections  list section types and data fields
library   vault index, molds we made, live-use ledger
crew      seven hands on one project; does not publish
```

Build flags: `--out DIR`, `--template modern|editorial|bold`, `--dark/--light`,
`--pages N`, `--brand NAME`, `--indexable`, `--max-copy-chars N`,
`--provider gemini|openrouter|openwork`, `--model ID`, `--allow-paid`,
`--max-tokens N`, `--no-fallback`.

## Output layout

```
sites/<name>/
  index.html      self-contained page(s): inline CSS + JS, system fonts,
                  inline SVG icons, gradient visuals; no external requests
  <slug>.html     extra pages (AI planner may create them)
  site.json       the IR - hand-editable, rebuild with --from
  site.json.bak   previous IR after a refine
  report.json     mode, provider/model, token ledger, warnings
  assets/         local images copied from the project
```

## Section types

hero, features, stats, steps, gallery, pricing, testimonials, faq, cta,
contact, about, team, menu, logocloud - see `python spidercaster.py sections`.

## Extending

Add a section type in three steps:

1. `lib/ir.py`: add the type to `SECTION_TYPES`, a `normalize_data` branch,
   and its data fields to `SCHEMA_PROMPT` + `SECTION_DOCS`.
2. `lib/render.py`: add a `render_section` branch.
3. `lib/offline.py`: optionally add a copy-mapping rule so the zero-token
   planner can produce it.

## Provider setup

| provider | env vars | notes |
|---|---|---|
| Gemini | `FORGE_GEMINI_KEY_FILE` (path to a key file; wins over env vars, fails closed if unreadable), else `GEMINI_API_KEY` / `GOOGLE_API_KEY` | free tier; tries AI Studio then Vertex express. Recorded fleet keys live in `V:\Research4\.secrets\` (e.g. `vertex_medicineman_key.txt`, `vertex_fruitaholics_key.txt`, `vertex_patriotfuelstop_key.txt`). Point the engine at one without pasting values: `$env:FORGE_GEMINI_KEY_FILE = 'V:\Research4\.secrets\vertex_medicineman_key.txt'`. If you get `Agent Platform API has not been used in project ...`, enable the API in the Google console for that project. |
| OpenRouter | `OPENROUTER_API_KEY` | `:free` models by default; `--allow-paid` for paid |
| OpenWork | `OPENWORK_API_KEY` + `OPENWORK_INFERENCE_BASE_URL` + `FORGE_OPENWORK_MODEL` | org-provided inference |

Model lists are overridable: `FORGE_GEMINI_MODELS`, `FORGE_OPENROUTER_MODELS`,
`FORGE_OPENWORK_MODEL` (comma-separated).
