Relume

## Product

Relume builds marketing sites by assembling a closed library of human-made sections. It does not publish raw model HTML as the product. The current homepage says the first input is a brief, then Relume builds a sitemap, wireframes, and a site you can publish on Relume or export. The homepage control also shows a file attachment before Generate. The August 24, 2026 Publish post says that brief can be a Notion doc, brand files, a URL, or Looms. The older sitemap procedure is still the public step-by-step: a short prompt (company, goals, notes), a language setting (over 20 languages, covering sitemap text and wireframe copy), then the generate control. The sample prompt asks for named pages and "4-8 sections" per page, and the doc says to keep the prompt shorter than that sample. `www.relume.io` redirects to `www.relume.ai`. The `/webflow` page is still live and still describes the older three-pass product: prompt to sitemap, sitemap to unstyled wireframes "with copy," then a style guide.

A human does approve a plan before the wireframed page exists. Generation builds the Home page first and waits. The person hits "continue generating pages," then edits page names, section names, and section descriptions before wireframes, because that text is the section prompt that picks the component and the generated copy. A second sitemap can sit beside the first; moving it to the top makes it primary. There is no named automated critic. After that, the style guide and Design View are a later pass, not the plan. Design View (July 8, 2025, still described as beta on that release) applies color, typography, and UI elements across the wireframes. The same release says it is not a Figma-style editor and not where spacing is finished pixel by pixel. Export to Figma or Webflow is the handoff. React export is still unstyled layouts only.

What changed since the 2026-10-01 notes: those notes said Relume does not document its own host. The live homepage and the August 24, 2026 release do. Publish (beta) hosts the site on Relume, on Cloudflare's edge, with a `relume.live` subdomain for review and a custom domain plus SSL on Launch hosting. The publish click is a separate action from export. Agents named Strategist, Designer, Copywriter, and Analyst are claimed to propose changes after launch. That proposal step is marketing on the release post, not a public procedure. Going live inside Webflow is still Webflow's publish, which the Relume import doc does not specify.

A section in Site Builder is one sitemap node tied to one wireframe section. Delete either and the other goes. The person can add a section from the section panel, drag it by the handle, swap a variant (which replaces the component), or replace the component and keep the copy. A main heading cannot be deleted, and testimonial text cannot be deleted, because Relume says that would break the component. Right-click "Change to page group" makes a nav folder that is not a page. A global section stays in sync wherever it is pasted. The sitemap doc's example is an FAQ. The Webflow import doc's example is a Navbar: on import, a global section becomes a Webflow component, and an existing component of the same name is reused rather than overwritten. Sitemap section colors are organizational only. They do not change generation or the Webflow export. The project file format inside Site Builder is not public.

Copy is generated. The sitemap doc says the prompt should produce bespoke copy per section. Ask AI on a wireframe can rewrite selected text shorter, longer, or to a line count. The rest of that option list is not public. Reset Copy replaces a page's text with latin filler. Reset Component can restore elements, copy, or both. That filler path is the opposite of a no-placeholder rule.

## Code libraries

Four public representations of one library. The Site Builder project that points at them is closed. Marketing pages say "1,000+" components. The pricing table, read as four columns (Free, Starter from $18/mo, Pro from $40/mo, Team from $36/mo with a 3-user minimum), lists Figma at 1,000+ on every column, and Webflow and React at 30 on Free and 1,000+ on the paid columns. The Figma library page says the kit is v3.7, updated October 2025, with 1,400+ components. The pricing FAQ still says 700+. A Japanese components index displayed 1747 next to the word Components. This report did not count the catalog. Treat every inventory number as a vendor claim, not a measurement.

Webflow library. Components are Client-First by Finsweet. Relume's own doc says the Webflow style guide is the Client-First style guide with a different Style Guide page, and the Webflow app only accepts the v3.0 cloneable. Public identifiers are slugs such as `navbar-8`, `header-107`, `layout-411`, `blog-sections/section_blog34`, and `application-shells/application-shell1`. Class roles named in the docs include `heading-style-h1`, `page-wrapper`, `main-wrapper`, `button`, and component classes such as `blog34_list-wrapper`. The customization doc says not to restyle `main-wrapper`, `page-wrapper`, text utilities (`text-weight-*`, `text-style-*`, `text-align-*`), or other structure classes. Figma and Webflow variables are color and size only, in Primitive and Semantic collections. A custom color is grouped by a slash name such as `Brand/Primary-500`. Some cards are tagged Interactions, Uncommon, Off-grid, Bento, Uses Attributes, or Uses Formly. Application shells publish a pairing rule: a level-3 sidebar or topbar stands alone; a level-2 sidebar pairs with a level-1 topbar, and the reverse. The component source inside Webflow is not public. The only public behavior script from Relume is `relumetech/powerups` on GitHub (MIT): a tooltip reposition script. The README says the copy that lands in Webflow is the minified form, and the repo's only powerup is tooltips.

Figma library. Duplicate kit v3.0 or later, then the Relume Figma plugin (login required) imports a style guide, wireframes, or a sitemap, and brings the generated copy with it. Later wireframe imports follow the style-guide colors already imported. The library page describes auto-layout, variables, variants, and a desktop/mobile variant swap. The kit file itself is not public code.

React library. Two npm packages, both latest on the registry on 2026-10-08. `@relume_io/relume-ui` at 1.3.1 is the primitive kit, not the section catalog. Its dist is six files (`index.js`, `index.mjs`, maps, and `index.d.ts`). Peer dependency is React `^18.2.0` and `react-dom`, plus Tailwind. It is the shadcn shape: Radix primitives, `class-variance-authority`, `clsx`, `tailwind-merge`, and a `cn` helper. The public type file exports Accordion, Badge, Breadcrumb, Button, Calendar, Carousel (Embla), Checkbox, Collapsible, Countdown, Dialog, DropdownMenu, Form (`react-hook-form`), Input, Label, Pagination, Popover, RadioGroup, Resizable panels, Select, Separator, Sheet, Sidebar, Skeleton, Slider, Switch, Table, Tabs, Textarea, Tooltip, VideoIframe, `useMediaQuery`, and `useSidebar`. The docs sidebar page says Sidebar is built on shadcn/ui. Button variants in the types are `primary`, `secondary`, `secondary-alt`, `tertiary`, `link`, `link-alt`, and `ghost`. `@relume_io/relume-tailwind` at 1.3.0 is a preset. The role of the file is `dist/tailwind.config.js` (also `.mjs` and `.ts`). It depends on `tailwindcss-animate` 1.0.7 and `@tailwindcss/typography` 0.5.15. Theme groups in that file are `screens`, `container`, `maxWidth`, `boxShadow`, `fontSize`, and `extend` colors named `brand`, `neutral`, `system`, `background`, `border`, `text`, and `link`, plus typography and animation keys. Screen keys, measured from that file: `sm` 480px, `md` 768px, `lg` 992px, `xl` 1280px, `xxl` 1440px. The container is full width until `lg` (992px) and `xl` (1280px). `fontSize.xs` is 0.75rem (12px) and `fontSize.sm` is 0.875rem (14px). `fontSize.md` is 1.125rem (18px). Those sizes are in the preset. They are not a published accessibility floor.

Section components are not in either npm package. React docs (intro fetched live; inner routes are a client-rendered app and returned only the intro shell on a direct fetch) say each section is TypeScript with props for headings, descriptions, images, and buttons, copied from the library or downloaded from Site Builder. A page export is one download of many files, because each section is multiple files, so a page cannot be copied onto the clipboard. A section can be copied or downloaded from the section panel after the export toggle is set to React. Sitemap export is the same toggle at the top right, then Export. The React docs warning still says style-guide and Design View export are not supported, with no ETA. The July 8, 2025 release said the new full-bleed feature and CTA sections were Figma and Webflow only, pending a React refactor. HTML export is the same sections as static markup styled with Tailwind, and the docs say it includes no JavaScript.

Relume Library MCP, the body of the July 1, 2026 release, is a remote server at `https://relume-library-mcp.relume.io/mcp`. The person signs in once. Setup adds a path alias, the Tailwind preset, and icons. The assistant searches the real library and fetches that component's code by slug into the project as editable React, with shared primitives. Named MCP tool functions are not public. The setup guide is a Notion page. A comparison block titled Wireframing 2.0 and Copywriting 1.5 (content count, brand fit, page-wide copy, Claude instead of GPT) is rendered on that July 2026 URL and also on the July 2025 and August 2026 what's-new URLs, so this report does not date those rows to July 2026 alone. The sitemap doc remains the procedure: title and description select the component.

A separate "your library" on the pricing page is storage for components the customer creates (caps listed as 10, 25, 300, 300 across the four plan columns) plus private sharing. That is not the Site Builder section schema. The June 2, 2025 release says wireframes can use 3,000+ Material icons, suggested from the copy, and that those icons export to Figma and Webflow. The icon file format is not public. `icons.relume.io` is linked from the Figma library page as an open-source icon set. This report did not inventory it.

## Mobile

Figma components ship a mobile variant. The library page says you swap the breakpoint variant and the content reflows. The July 2025 kit note says new components were added in desktop and mobile variants. Webflow components are described as responsive and built on Client-First. Client-First's utility docs name three hides: `hide-tablet`, `hide-mobile-landscape`, and `hide-mobile-portrait`. Relume does not publish a pixel table for those Webflow breakpoints. The measured pixel list is the React preset above (480, 768, 992, 1280, 1440). The wireframe editor has a responsive-device control at the bottom right. Comments are stored per device: switch device, then comment. The names and widths of those devices are not public. A mobile-menu procedure (drawer, focus trap, tap size) is not public. Application-shell pairing is the closest public nav rule.

Publish's August 2026 post claims every component is tested "across every breakpoint and viewport" so nothing collapses on mobile. That is a claim. The viewport list and any measured result are not public. No Relume page opened here requires 18px body text, 16px chrome, a 44px target, or a 4.5:1 contrast figure. The Client-First sizes doc recommends 14px type when 16px is too large. The React preset includes 12px and 14px steps. A contrast audit of the preset colors was not run.

## Dynamic behavior

Site Builder has no public CMS. After a Webflow import, blog components are built to match Webflow's Collection List Wrapper, Collection List, and Collection Item. The doc walks Blog 34 (`blog-sections/section_blog34`) and a slider (Blog 66) that needs Finsweet Attributes CMS Slider, plus nested collections via Finsweet CMS Nest or CMS Filter. A sitemap color can mark a section the person intends for the CMS. That color does not export. A Relume-hosted CMS is not public.

Accounts: a Relume login is required for the builder, the Webflow app, the Figma plugin, and the MCP. Publish collaboration invites editors with no per-seat charge, according to the release post. End-user accounts on the published site are not public.

Forms: the Webflow style guide styles native Webflow form fields. Multi-step forms are Formly, an external script (`multi-step.js` from the `videsigns/webflow-tools` package on jsDelivr) plus attributes `data-form` (`multistep`, `step`, `back-btn`, `next-btn`) and `data-enter`. Checkbox and radio active styles need Finsweet Attributes Input Active. Formly runs only on a published Webflow site, not in the Designer. The free Formly plan covers the multi-step components Relume ships; conditional logic is Formly Pro. Publish hosting has its own forms: submissions land in the Relume dashboard. The pricing page states both "20" submissions per month and "unlimited." Which column is which is not public from the text layout. React primitives include `react-hook-form`. HTML export has no JavaScript, so those forms do not submit by themselves.

Other client JavaScript: Finsweet Attributes on tagged Webflow components, the minified tooltip powerup, and, in the React kit, Radix, Embla, and Framer Motion. `useMediaQuery` is exported. The Site Builder app runtime is not public. Publish's runtime, beyond "Cloudflare edge," is not public. Analytics on published sites (visitors, page views, top pages, a 7-day window on one cell, full access on another) is a hosted product, not a script the docs show how to install.

## Already in SpiderCaster

The plan is a package frame, not a generated sitemap. `library/frames/*.json` (`spidercaster-frame/1`) names the section order. `welcome-scroll` is `hero`, `about`, `features`, `gallery`, `faq`, `contact`, nav `one-page`. `compose` reads real `copy/` files, reorders only sections that copy already produced, paints one mold, and inserts one catalog part per section plus a header and a footer. It writes `structure.json`, `site.json`, and `report.json` in that same pass, and the HTML is noindex. There is no pause that shows Home and waits before the rest of the pages. There is no second generated sitemap.

The section store is the catalog under `V:\streams\webdev\tools\parts` (208 rows) plus the frame list. `tools apply` can append, replace, or paint a mold, and it refuses a path in `lock.txt`. A global header and footer are inserted once. A synced middle section, a page group that is not a page, and a variant swap that keeps generated copy do not exist, because copy is not generated. The mold (`palette`, `type_lead`, `nav`, `template`) is chosen before render. Design View's post-wireframe restyle is not how a mold works, and a mold already live on another site stays refused. `warmth-authority` is already live on movelixir.com and must not be bound live again.

Mobile floors are already in `lib/check.py`: body 18px, chrome 16px, contrast 4.5:1 (large text 3:1), tap 44px, no sideways overflow at 360, 390, and 412, sticky header, mobile drawer, skip link, scroll-margin. `visit` measures at 390 and 1280 when Playwright is installed. `lib/render.py` already emits a viewport meta, one h1 on the hero, a nav toggle with `aria-expanded` and `aria-controls`, and a skip link.

SEO already emitted by `render_page`: `<title>`, meta description, relative canonical (`index.html` or the slug file), `og:title`, `og:description`, `og:type` of `website`, `og:image` only when the hero already has a local image, WebSite JSON-LD with name and description and no rating, and FAQPage JSON-LD only from faq pairs that are also visible. `noindex, nofollow` stays until a human runs `library bind --live`. The checker refuses SAMPLE, lorem, and placeholder text, hotlinked images, a bad canonical, and aggregateRating. A `sitemap.xml` file and a `robots.txt` file were not found in `lib/`. Index control is the meta robots tag, not a robots file. There is no 301 table, no custom-code slot, and no analytics pixel.

There is no CMS, no account system, and no form backend. The page is static HTML from the standard library. Client behavior that does exist is the mobile drawer and the sticky header, not a component runtime. React, Tailwind, shadcn, and a remote component fetch are not in the build.

## Worth building

Two static pieces, reimplemented, and only from copy that already exists.

A plan stop before paint. Relume's useful gate is that the person sees the page list and edits section order before the wireframe is generated. `compose` currently writes the plan and the HTML together. A stdlib step can write `structure.json` from the chosen frame and the `copy/` files, then stop. Render runs only after a person accepts that order. It must not invent a page, a section, or a sentence, and it must not keep a second generated sitemap.

A part choice from the copy's shape. Relume picks a 2-plan layout when the section description says two plans. The same idea, without a model: if a section type has more than one catalog part, pick from the count of items and whether a local image path is already in that copy file. Still one part per section. Still `tools apply` and `lock.txt`.

Do not import Client-First class names, the Tailwind preset, `@relume_io/relume-ui`, or a slug fetch. The preset's 12px and 14px steps are under the checker floors. Do not add Design View restyle of a live mold, Publish hosting, a form that posts to a dashboard, a review count, latin filler, or an agent that edits the site after launch.
